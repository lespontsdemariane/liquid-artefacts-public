# liquid-artifacts-public

The shared, open-source, community repository for **artifacts** generated by [liquid-os](https://github.com/lespontsdemariane/liquid-os).

## What is an artifact?

In liquid-os, an *artifact* is a catalogue object produced by the platform's skill-chain compilers: a **schema**, **permission**, **task**, **workflow**, or **view**. Artifacts are generated by AI, then published through a human-signed publication gate (or auto-published for lower-risk tiers) before they become part of an instance's live catalogue.

Agentic RAG only ever *combines* what is already published — it never generates a new artifact. Generation is reserved for the compiler skills themselves.

## What lives in this repo

Generated **task code**: the Python task functions produced by the task compiler, and the tests written alongside them. The layout is fixed, because liquid-os fetches these paths by name at a recorded commit rather than searching for them:

```
tasks/<task_ref>.py                    the implementation
tasks/<task_ref>.requirements.txt      optional, only when the task declares extra dependencies
tests/test_<task_ref>.py               the tests
```

Two conventions worth knowing before reading the history:

- **Every task arrives on its own branch**, named `liquid-task-compiler/<task_ref>`, opened as a pull request by the compilation that produced it. The commit message is the task's own description.
- **The tests are written by the AI, not by the author of the implementation.** That is deliberate: the tests are meant to be evidence independent of whoever wrote the code, including when a human edits it afterwards.

A merged pull request here does not mean a human read the code. A task with no side effects is a lower-risk tier and its pull request is merged and published automatically; only higher tiers require a recorded human review before publication.

## How this repository is used

- **Pre-seeded** into every liquid-os instance's registry of artifact repositories, out of the box — it is the public destination a compilation resolves to when it is not targeting a private repository.
- **Read-only by default** — no write credential is configured until an admin deliberately opts in.
- **Opt-in only for writes, never a silent default** — pushing here for a given task is an explicit, per-compilation choice. This repository must never become an accidental destination for a company's proprietary business logic; instances that want to keep generated code private configure their own private repository instead (see [liquid-artifacts-private](https://github.com/lespontsdemariane/liquid-artifacts-private) for the pattern).

## Current state

Being pre-seeded is not the same as being wired up. Today an instance can be pointed at this repository as a write destination, but **nothing reads from it**: there is no cross-repository artifact search, and no import of what other instances have published. Those are the capabilities that would make this a genuinely shared catalogue rather than a shared bucket, and they are planned rather than built. This section will shrink as that changes.

## Contributing

Anything merged here is shared with every liquid-os instance that opts in, so an artifact is only worth publishing publicly when it is genuinely reusable beyond the instance that produced it: a generic transformation, a widely-applicable validation rule, a standard integration. Business logic specific to one organisation belongs in that organisation's own private repository.

Pull requests here are normally opened by a machine. A human one is welcome, but it should carry both an implementation and its tests, in the layout above, so the platform can fetch it the same way.

## Naming

Identifiers in liquid-os — object types, field names, task refs, workflow refs — are always **English, lowercase, snake_case**, whatever language the need was expressed in: `destroy_encryption_key_v1`, never a transliteration. The rule is enforced in the platform at the publication boundary, so a task ref that does not follow it cannot be published here in the first place.
